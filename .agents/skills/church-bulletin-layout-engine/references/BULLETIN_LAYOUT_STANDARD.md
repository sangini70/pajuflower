# 주보 레이아웃 표준

이 문서는 파주꽃동산교회 승인 주보를 기존 Vite 정적 생성 구조로 출력할 때 적용하는 기준이다. 프로젝트 헌법, `AGENTS.md`, `PAJU_FLOWER_WORKFLOW.md`, `WEBSITE_BRIEF.md` 및 승인 규칙을 대체하지 않는다.

## 1. 출력 레이아웃

- PC 웹은 기존 주보 전용 스타일의 2단 정보 배치를 유지한다.
- 모바일 웹은 1단으로 전환하고 표와 본문이 화면 폭을 넘지 않게 한다.
- 인쇄는 `dist/content.css`의 A4 `@page` 규칙과 행·블록 분할 방지 규칙을 사용한다.
- 페이지 수를 줄이기 위해 승인된 내용을 삭제하거나 글자를 과도하게 축소하지 않는다.

## 2. 원문 보존

- `content/bulletins.json`이 공개 주보의 원본 데이터다.
- 승인된 원문의 문장, 숫자, 이름, 날짜, 순서, 표의 행·열을 보존한다.
- 섹션 제목만 출력되고 본문이 비어 있으면 정상 출력으로 보지 않는다.
- 종이 원본에 없는 설명·요약·출처 문구를 주보 본문에 추가하지 않는다.
- `REFERENCE/` 원본, 초안, 내부 경로와 승인 메타데이터는 공개 HTML에 출력하지 않는다.

## 3. 데이터와 렌더링 계약

현재 `scripts/bulletin-layout.mjs`의 `numbered-list` 렌더러는 항목을 다음 형식으로 처리한다.

- 객체: `{ number, lines[] }`
- 배열: `[number, line1, line2, ...]`
- 문자열: 표시 순서에 따라 번호를 부여하고 문자열을 본문으로 출력

이 계약을 변경할 때는 기존 10월 4일·11일·18일 주보 회귀를 확인한다. 공개 등록 필터는 `webEdition.sections`의 승인된 공개 필드만 보존한다.

## 4. 표와 예배 순서

- 데이터의 실제 행·열 수를 기준으로 표를 생성한다. 내용을 합치거나 열을 삭제하지 않는다.
- 2열·3열·4열 표를 각각 실제 행 길이에 맞춰 출력한다.
- 주일낮예배 표의 선행 `*` 열은 전용 마커 열로 처리한다.
- 현재 기준 CSS에서 마커 열은 PC·모바일 모두 1rem을 기준으로 하며, 예배 순서명과 불필요하게 벌어지지 않아야 한다.
- 마커가 없는 행도 순서명 시작 위치를 유지한다.
- 표 셀은 줄바꿈 가능해야 하며 모바일 가로 넘침을 유발해서는 안 된다.

## 5. 공개 및 연결 규칙

- 개인정보·민감한 가족·건강·사고 정보와 공개 승인되지 않은 항목은 출력하지 않는다.
- 주보의 `relatedSermonId`는 실제 공개 설교 ID와 일치해야 한다.
- 설교 페이지와 주보 페이지의 양방향 링크, 기존 URL, canonical, Open Graph, JSON-LD, sitemap을 유지한다.

## 6. 필수 검증

새 주보마다 다음 순서를 사용한다.

1. 원본 확인
2. 비공개 초안 작성
3. 원문 대조
4. 공개 승인
5. 정식 등록
6. HTML 생성
7. 자동 검증
8. 실제 브라우저 시각 검수
9. 별도 배포 승인

자동 검증 명령:

```text
npm run validate
npm run draft:test
npm run register:test
npm run e2e:test
npm run generate
npm run build
git diff --check
```

다음은 FAIL이다.

- 제목만 있고 승인된 본문이 비어 있는 경우
- 원본의 공개 가능한 항목이 누락되는 경우
- 예배 순서표의 마커 열이 과도하게 벌어지는 경우
- 모바일 가로 넘침이 발생하는 경우
- 개인정보 또는 비공개 원본이 공개되는 경우
- 기존 주보·설교·홈페이지 회귀가 발생하는 경우

자동 검증만으로 실제 화면을 확정하지 않는다. PC 1440px·1280px, 모바일 390px·360px에서 표, 줄바꿈, 빈 공간, 가독성을 확인하고, 브라우저를 사용할 수 없으면 `REVIEW_REQUIRED`로 보고한다.
